# cuoti-ledger

把「这道题我卡在哪」记成一条可回溯的记录，按知识点算账，一周一张卷子。

## 何时用

命中任意一条就加载：

- 用户发来数学题、卷子、真题的照片或文字，要求批改、讲题、对答案
- 用户说「这题记一下」「以后帮我整理错题」
- 用户问「我最近哪块最差」「哪个知识点错得最多」
- 用户要「错题周报」「把这周的错题整理出来」

不适用：纯数学问答（他只是想懂一个概念，没有自己的题）、和做题无关的查公式。

## 核心：单位是知识点，不是题

同一道题不会再考，同一个断点会。所以每道题必须挂 `points`（1–3 个细知识点），周报靠它统计「哪个知识点错了三次」。没挂知识点的题，记了等于白记。

## 三步流程

### 第一步：判断这算不算「该记的题」

算：

- 他做错了的题（尤其是思路对的、只是算错的）
- 他卡住、跳过、含糊带过的题
- 他做对了但方法绕远的题

不算：

- 蒙对的
- 明显笔误、抄错题
- 你已经讲过、他当堂就会的（那种下次再错再说）

宁少勿多：一次批改收 2–5 道，收 20 道他一道都不会重做。

### 第二步：落库

先看本仓库的 `AGENTS.md`（工作约定）与 `SPEC.md`（字段定义），再执行：

```bash
python cuoti.py add --file seed/<week>.json     # 批量，推荐
```

单道用行内参数：

```bash
python cuoti.py add "求 ∫₀¹ x·√(1−x²) dx" --topic 一元积分 \
  --point 定积分换元 --point 换元换限 --kind 计算 \
  --my-work "上下限还写 0 到 1，结果 2/3" \
  --stuck "换元之后没换上下限" \
  --answer "1/3" --fix "换元三件套一起换：被积式、dx、上下限"
```

三个字段决定这条记录有没有用：

| 字段 | 要求 |
|---|---|
| `points` | 必填，1–3 个细知识点，第 0 个是主知识点 |
| `stuck` | 必填，具体到「断在哪一步」，不写「粗心」「不熟」 |
| `kind` | `概念` / `方法` / `计算` / `审题` / `漏解` 五选一 |

### 第三步：用户说「会了」时划掉

```bash
python cuoti.py solve 20261123-001      # 搞懂了（别名 learn）
python cuoti.py unsolve 20261123-001    # 又不会了，放回去（stuck 保留）
python cuoti.py star 20261123-001       # 收藏：典型题，值得反复看
python cuoti.py unstar 20261123-001
```

**这是他唯一的进度信号，你不要替他按。** 他说「听懂了」≠「能独立做出来」，不算 `solve`。

### 第四步：回话

三行以内：记了几道、最该补哪个知识点、周报里会出现在哪些模块。不要贴 JSON，不要复述全套解法。

## 不要做

- 不要替用户判定他会了
- 不要覆盖已有的 `stuck` / `fix` / `answer`（重复 `add` 自动只补空缺）
- 不要编答案；没把握就留空
- 不要用 LaTeX 写题干（报告不联网，不渲染）；用 `x²`、`√2`、`∫₀¹`
- 不要自己搞一套新字段——要增字段先改 SPEC 版本
- 不要手改 `data/mistakes.json` 里的 `solved`（那是他的按钮）

## 参考

- `SPEC.md` — 数据格式、统计口径、渲染与打印契约
- `AGENTS.md` — 仓库内的工作约定、kind 与 topic 对照表
- `examples/sample.json` — 一份可直接导入的样例（12 道考研题）
